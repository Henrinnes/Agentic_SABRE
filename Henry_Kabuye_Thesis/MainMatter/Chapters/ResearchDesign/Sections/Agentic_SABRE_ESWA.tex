\section{Introduction}
\label{sec:eswa_intro}

\lettrine{T}{he} preceding chapter demonstrated that integrating data augmentation, explainable AI, and Monte Carlo Dropout uncertainty quantification yields a robust single-agent framework for ransomware detection, achieving F1-scores of up to 0.9978 on the RDset and RanSAP datasets \cite{kabuye2025explainable}. However, that work employed a single unified model that processed all available feature signals together, without distinguishing between fundamentally different types of evidence. Ransomware exhibits two distinct behavioural signatures: a \emph{semantic} signature encoded in the structural metadata of executable files (import tables, section entropy, PE flags), and a \emph{behavioural} signature expressed through runtime I/O access patterns, memory allocation dynamics, and filesystem activity. These two signal types have different statistical properties, different distributional characteristics, and are most naturally captured by different model architectures operating on different datasets.

This chapter introduces \textbf{Agentic SABRE} (\emph{Semantic-Behavioural Arbitration for Ransomware Evaluation}), a multi-agent framework that decomposes ransomware detection into two specialised agents — a Semantic Agent and a Behavioural Agent — each trained independently on its own modality-specific dataset. The framework fuses their outputs through a learned Decision Agent and applies an uncertainty-aware triage policy that governs whether the system may act autonomously or must escalate suspicious activity to a human analyst. Unlike the prior single-agent approach, which used uncertainty primarily as a post-hoc diagnostic signal, Agentic SABRE operationalises uncertainty as an \emph{executive control variable}: it is embedded directly into the triage decision logic, determining whether high-risk predictions trigger autonomous containment or are held for human review.

The framework makes five principal contributions beyond the IEEE Access baseline:
\begin{itemize}
    \item A \textbf{multi-agent architecture} that assigns semantic embeddings and behavioural telemetry to structurally heterogeneous specialised agents, replacing the single-model design with a modular pipeline.
    \item An \textbf{uncertainty-aware inference mechanism} using Monte Carlo Dropout at each agent, enabling both a predictive mean probability and an epistemic uncertainty estimate to be produced per agent per sample.
    \item A \textbf{score-space CTGAN augmentation} strategy that synthesises score vectors in the low-dimensional fusion space rather than augmenting raw features, preserving the uncertainty geometry of the agents while improving the Decision Agent's training distribution.
    \item A \textbf{formal triage policy} governed by a risk threshold $\tau$ and an uncertainty budget $\kappa$, with a stricter autonomous containment pair $(\tau_\text{high}, \kappa_\text{low})$, creating a calibrated computational contract between automated defence and analyst oversight.
    \item \textbf{Post-hoc explainability} via gradient saliency, permutation importance, and counterfactual analysis at both the agent and fusion levels, enabling local and global interpretation of all system decisions.
\end{itemize}

\section{Background and Motivation}
\label{sec:eswa_background}

\subsection{Limitations of Monolithic Detectors}

Ransomware has become a dominant form of cybercrime, driven by increasingly sophisticated techniques for evasion, polymorphism, and operational stealth. Traditional approaches to ransomware detection have relied on signature matching, heuristic rule sets, or simple statistical anomaly detection. Although effective for well-known threats, such approaches degrade rapidly in the presence of obfuscation, encryption, behavioural drift, and previously unseen attack families. Machine learning has emerged as a powerful tool, leveraging system call traces, API telemetry, filesystem access patterns, and related forensic signals \cite{zahoora2022Deep, alraizza2023ransomware}. However, purely model-based detection suffers from three persistent challenges.

First, data imbalance remains severe: benign activity dominates operational telemetry. Oversampling techniques such as SMOTE and generative models such as CTGAN have been proposed to mitigate minority-class scarcity \cite{chawla2002smote, xu2019ctgan}. Second, semantic modelling using transformers and embedding-based architectures has improved contextual understanding of system logs and API sequences, yet these models often lack robustness under concept drift and out-of-distribution conditions \cite{fernando2020study}. Third, most existing machine learning detectors provide only point predictions and do not quantify predictive uncertainty, making it difficult to determine whether a model's output is reliable enough to drive autonomous containment decisions \cite{gal2016dropout, gawlikowski2023Uncertainity}.

The single-agent framework developed in the preceding chapter, like most prior ransomware detectors, processes all available features through a single learned model. This design imposes two structural limitations. First, it assumes that semantic and behavioural features can be jointly represented in a single feature space, which may not hold when the two modalities have fundamentally different statistical properties. Semantic PE-header embeddings are typically high-dimensional, sparse, and cluster strongly by malware family, whereas runtime telemetry features are low-dimensional, continuous, and exhibit heavy class overlap due to behavioural polymorphism and living-off-the-land techniques \cite{Ceschin2022ConceptDrift}. A single model must simultaneously learn both types of structure, potentially compromising its performance on each. Second, monolithic models provide a single point prediction or, at best, a single scalar uncertainty estimate for the joint input. This makes it impossible to determine \emph{which modality} is driving uncertainty.

\subsection{The Case for Multi-Agent Uncertainty-Aware Design}

Recent work in cybersecurity has begun to explore uncertainty quantification as a means of addressing model unreliability in deployment \cite{gal2016dropout, gawlikowski2023Uncertainity, kabuye2025explainable}. Techniques such as Monte Carlo Dropout and deep ensemble variance estimation allow detectors to express confidence levels alongside predicted probabilities. Nevertheless, most existing cybersecurity systems use uncertainty only as an auxiliary diagnostic tool rather than integrating it into a structured triage or escalation policy. As a result, model uncertainty is rarely incorporated into actionable decision-making. Parallel to these developments, neuro-symbolic and multi-agent architectures have gained traction for their modularity and interpretability \cite{Besold2021neurosymbolicsurvey}. However, most prior systems treat multi-agent fusion as a simple ensemble procedure, and few integrate uncertainty-aware reasoning or explicit policies for calibrated automation.

The multi-agent design in Agentic SABRE addresses both limitations by assigning each modality to a dedicated agent with its own uncertainty estimate. As noted in \cite{Ispahany2024Survey}, most ransomware detection surveys identify the lack of uncertainty-aware decision mechanisms as a key gap; the literature overwhelmingly focuses on improving classification accuracy while leaving uncertainty unexploited at the system level. Agentic SABRE takes the next step by \emph{operationalising} this uncertainty within a formal triage policy.

A critical distinction separates Agentic SABRE from conventional ensemble methods. Ensemble detectors aggregate predictions from multiple models trained on the same feature space, typically via majority vote or average probability. Agentic SABRE differs in three respects. First, its two agents operate on \emph{structurally heterogeneous} input spaces — 384-dimensional PE embedding vectors versus 16-dimensional runtime telemetry statistics — making them complementary by design rather than redundant. Second, the triage decision conditions on per-agent \emph{epistemic uncertainty}, not merely on the posterior probability; a standard ensemble produces no such per-model uncertainty signal. Third, the triage policy is an \emph{executable control mechanism} that can formally withhold autonomous action under ambiguity — a property that soft label aggregation does not possess.


\section{Related Work}
\label{sec:eswa_related}

\subsection{Machine Learning for Ransomware Detection}

Machine learning approaches to ransomware detection range from classical models operating on handcrafted features to deep learning systems that learn representations from raw telemetry \cite{razaulla2023age, fernando2020study}. Classical methods such as random forests and support vector machines have shown strong performance on well-curated datasets but degrade rapidly under concept drift as ransomware tactics evolve \cite{Fernando2024FeSAD, Ceschin2022ConceptDrift}. Deep learning approaches leveraging CNN and LSTM architectures on system call traces and filesystem access patterns achieve strong in-distribution performance but suffer from overconfidence on out-of-distribution samples \cite{zahoora2022Deep}. Transformer-based models and LLM-derived embeddings have also been explored for security log analysis \cite{tian2025llmsurvey, ZhangLZYHY25}, but these systems are typically standalone classifiers without uncertainty-aware fusion or structured triage logic. Recent work has also explored deep learning and blockchain-based frameworks for malware detection in IoT environments \cite{pawar2024securing}, underscoring the breadth of architectural approaches being applied to adaptive threat analysis.

\subsection{Data Augmentation and Imbalance Handling}

Imbalanced datasets remain a pervasive challenge in ransomware detection because benign activity vastly outweighs malicious traces. Oversampling approaches such as SMOTE \cite{chawla2002smote} and generative tabular models such as CTGAN \cite{xu2019ctgan, ashrapov2020tabular} have been widely adopted to mitigate class imbalance. While these methods improve training stability, they are typically employed only at the data preprocessing stage and are rarely integrated into multi-stage detection pipelines. Agentic SABRE differs by applying CTGAN not to raw features but to the \emph{score space}, enriching rare high-risk cases entering the fusion layer without altering agent-level probabilities or uncertainties.

\subsection{Uncertainty Quantification in Cybersecurity}

The importance of uncertainty quantification in cybersecurity has been recognised by several recent works \cite{gawlikowski2023Uncertainity, Doan2024uncertainBay}. Monte Carlo Dropout \cite{gal2016dropout}, deep ensembles, and Bayesian neural networks have been applied to intrusion detection and malware classification. However, existing systems consistently use uncertainty as a \emph{diagnostic output} rather than as a \emph{governance variable} that constrains system behaviour. Agentic SABRE advances this direction by embedding per-agent uncertainty directly into an executable triage policy with formal threshold semantics.

\subsection{Multi-Agent and Neuro-Symbolic Approaches}

Multi-agent learning has been explored for adaptive intrusion detection, cooperative anomaly detection, and adversarial resilience \cite{AdversarialCooperationLLM2024, MultiAgentAdaptiveDetection2023}. Parallel advances in neuro-symbolic systems highlight the benefits of combining neural representations with symbolic rules and knowledge bases \cite{Besold2021neurosymbolicsurvey, YangSBK25}. However, prior systems typically lack: (i) agent-level uncertainty estimation, (ii) uncertainty-aware fusion, and (iii) operational triage policies linking uncertainty and risk to automated or human-in-the-loop decisions. Agentic SABRE directly addresses all three gaps.

\section{The Agentic SABRE Architecture}
\label{sec:eswa_arch}

\subsection{System Overview}

Agentic SABRE is a five-stage pipeline illustrated in Figure~\ref{fig:eswa_pipeline}. Stage~1 performs hybrid feature extraction: PE-header metadata is embedded using a sentence-transformer encoder to produce 384-dimensional semantic vectors, and runtime I/O traces are processed via sliding-window statistics to produce 16-dimensional behavioural feature vectors. Stage~2 applies SMOTE at the feature level independently for each modality. Stage~3 trains the Semantic and Behavioural CNN agents independently with Monte Carlo Dropout enabled, each producing a mean probability and uncertainty estimate per sample. Stage~4 collects agent score tuples, applies CTGAN augmentation in the score space, and trains the Decision Agent MLP on the augmented score dataset. Stage~5 implements the uncertainty-aware triage policy at deployment time. The complete training and deployment procedure is formalised in Algorithm~\ref{alg:eswa_pipeline}.

\subsection{Semantic Agent}

The Semantic Agent processes 384-dimensional PE-header embedding vectors derived from structured metadata — import tables, section entropy values, PE flags, version strings, and related static attributes — extracted from the RDset dataset \cite{mathur2020ransomware}. Embeddings are computed using a pre-trained sentence-transformer encoder \cite{ReimersG19} applied to concatenated attribute strings, mapping each executable to a dense semantic representation. The agent architecture is a 1D CNN with depth $L = 3$, kernel size $K = 3$, and $C = 64$ filters per convolutional layer, followed by ReLU activation, batch normalisation, global average pooling, and a sigmoid output unit. A dropout layer ($p_\text{drop} = 0.3$) is placed before the output unit and retained active at inference time to enable Monte Carlo sampling.

\subsection{Behavioural Agent}

The Behavioural Agent processes 16-dimensional feature vectors derived from the RanSMAP dataset \cite{hirano2022ransap, hirano2025ransmap}, which records runtime I/O and memory access telemetry for ransomware-infected and benign hosts. Features are computed over fixed 30-second sliding windows and include: LBA (Logical Block Address) variance for read and write operations, GPA (Guest Physical Address) variance for memory reads and writes, memory operation counts, I/O entropy, and total bytes transferred. Formally, for a window of $n$ measurements $\{x_j\}$:
\begin{align}
\text{Var}(x) &= \frac{1}{n}\sum_{j=1}^n (x_j - \bar{x})^2, \\
\mathcal{H}(x) &= -\sum_{j=1}^n p(x_j)\log_2(p(x_j) + \epsilon).
\end{align}
The agent architecture mirrors the Semantic CNN with $L = 3$ convolutional layers, $K = 3$, $C = 64$ filters, and a dropout layer before the sigmoid output unit ($p_\text{drop} = 0.3$).

\subsection{Monte Carlo Dropout Uncertainty Estimation}

Both agents use Monte Carlo (MC) Dropout \cite{gal2016dropout} to quantify epistemic uncertainty. The formal procedure is given in Algorithm~\ref{alg:eswa_mc_dropout}. At inference time, the dropout layers are kept active, and $T = 30$ stochastic forward passes are performed for each sample. The predictive mean probability and standard deviation across passes are:
\begin{equation}
\bar{p} = \frac{1}{T}\sum_{t=1}^T p_t, \qquad
\sigma = \sqrt{\frac{1}{T}\sum_{t=1}^T (p_t - \bar{p})^2},
\label{eq:eswa_mcdropout}
\end{equation}
where $p_t$ is the output of the $t$-th stochastic forward pass. This yields per-agent pairs $(\bar{p}_\text{sem}, \sigma_\text{sem})$ and $(\bar{p}_\text{beh}, \sigma_\text{beh})$.

MC Dropout was chosen over deep ensembles and Bayesian neural networks for three practical reasons: it requires no architectural changes beyond retaining dropout at inference; its per-sample cost of $T$ forward passes is substantially lower than training and maintaining $M \geq 5$ independent ensemble members; and the agents' training pipelines already include dropout regularisation, so no additional training overhead is incurred.

\subsection{Score Fusion and Decision Agent}

The fused score vector is assembled from the two agent outputs:
\begin{equation}
\mathbf{s} = \begin{bmatrix} \bar{p}_\text{sem} \\ \bar{p}_\text{beh} \end{bmatrix},
\label{eq:eswa_scorevec}
\end{equation}
optionally extended with per-agent uncertainties at deployment to form the full four-dimensional vector:
\begin{equation}
\mathbf{v} = \bigl(\bar{p}_\text{sem},\; \bar{p}_\text{beh},\; \sigma_\text{sem},\; \sigma_\text{beh}\bigr) \in \mathbb{R}^4.
\label{eq:eswa_fullvec}
\end{equation}
A CTGAN \cite{xu2019ctgan} is trained on the score dataset $\mathcal{D}_S = \{(\mathbf{s}_i, y_i)\}$ to generate synthetic score vectors that enrich the minority class in score space (Algorithm~\ref{alg:eswa_ctgan}). The augmented dataset $\mathcal{D}_S \cup \tilde{\mathcal{D}}_S$ is used to train the Decision Agent MLP, a two-hidden-layer network (64 units per layer, ReLU activations, sigmoid output) that learns a mapping $f: \mathbb{R}^4 \to [0,1]$ producing the fused risk estimate:
\begin{equation}
\hat{p} = f(\mathbf{v}).
\label{eq:eswa_fusedp}
\end{equation}

\subsection{Uncertainty Aggregation}

To ensure conservative triage behaviour, agent-level uncertainties are aggregated via a max-operator:
\begin{equation}
\sigma_\text{max} = \max(\sigma_\text{sem},\; \sigma_\text{beh}),
\label{eq:eswa_sigmamax}
\end{equation}
so that elevated uncertainty in \emph{either} modality constrains autonomous action. This conservative choice prevents high semantic confidence from overriding high behavioural uncertainty, ensuring that the system seeks human oversight whenever any modality is epistemically unreliable.

\begin{algorithm}[ht]
\caption{Agentic SABRE: Training and Deployment Pipeline}
\label{alg:eswa_pipeline}
\begin{algorithmic}[1]
    \State \textbf{Input (training):} Raw semantic data $D_{\text{sem}}$, behavioural logs $D_{\text{beh}}$
    \State \textbf{Input (deployment):} New sample $x_{\text{sem}}, x_{\text{beh}}$
    \State \textbf{Output (deployment):} Decision $\in \{\text{AUTO-CONTAIN}, \text{ESCALATE}, \text{ALLOW}\}$
    \Statex \textbf{// Phase 1: Hybrid feature extraction}
    \State Extract semantic embeddings $\mathbf{z}_i$ from $D_{\text{sem}}$ using encoder $\mathcal{E}(\cdot)$
    \State Extract behavioural feature vectors $\mathbf{b}_i$ from $D_{\text{beh}}$ via sliding-window statistics
    \Statex \textbf{// Phase 2: Feature-level augmentation}
    \State Apply SMOTE to $\{\mathbf{z}_i\}$ and $\{\mathbf{b}_i\}$ independently to address class imbalance
    \Statex \textbf{// Phase 3: Train base agents with MC Dropout}
    \State Train Semantic Agent CNN $A_{\text{sem}}$ on $\{\mathbf{z}_i\}$
    \State Train Behavioural Agent CNN $A_{\text{beh}}$ on $\{\mathbf{b}_i\}$
    \Statex \textbf{// Phase 4: Score-level augmentation and Decision Agent}
    \For{each training sample $i$}
        \State Compute mean scores $\bar{p}_{\text{sem}}^{(i)}$, $\bar{p}_{\text{beh}}^{(i)}$ via MC Dropout (Alg.~\ref{alg:eswa_mc_dropout})
        \State Form score vector $s_i = [\bar{p}_{\text{sem}}^{(i)}, \bar{p}_{\text{beh}}^{(i)}]$
    \EndFor
    \State Train CTGAN on $\{(s_i, y_i)\}$ and obtain augmented scores $\tilde{\mathcal{D}}_S$ (Alg.~\ref{alg:eswa_ctgan})
    \State Train Decision Agent $A_{\text{dec}}$ on $\mathcal{D}_S \cup \tilde{\mathcal{D}}_S$
    \Statex \textbf{// Phase 5: Deployment-time inference and triage}
    \State Obtain $(\bar{p}_{\text{sem}}, \sigma_{\text{sem}})$ for $x_{\text{sem}}$ via MC Dropout
    \State Obtain $(\bar{p}_{\text{beh}}, \sigma_{\text{beh}})$ for $x_{\text{beh}}$ via MC Dropout
    \State Form $\mathbf{v} = [\bar{p}_{\text{sem}}, \bar{p}_{\text{beh}}, \sigma_{\text{sem}}, \sigma_{\text{beh}}]$ and compute $\hat{p} = A_{\text{dec}}(\mathbf{v})$
    \State Compute $\sigma_{\max} = \max(\sigma_{\text{sem}}, \sigma_{\text{beh}})$
    \State Apply triage policy (Alg.~\ref{alg:eswa_triage}) using thresholds $(\tau, \kappa, \tau_{\text{high}}, \kappa_{\text{low}})$
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[ht]
\caption{MC Dropout Uncertainty Estimation for a Neural Agent}
\label{alg:eswa_mc_dropout}
\begin{algorithmic}[1]
    \State \textbf{Input:} Trained neural agent $A$ with dropout layers, sample $x$, number of passes $T$
    \State \textbf{Output:} Predictive mean $\bar{p}$, epistemic uncertainty $\sigma$
    \State Set dropout modules to training mode (active at inference)
    \For{$t = 1$ to $T$}
        \State $p_t \gets A(x)$ \Comment{stochastic forward pass with dropout}
    \EndFor
    \State $\bar{p} \gets \frac{1}{T}\sum_{t=1}^{T} p_t$
    \State $\sigma \gets \sqrt{\frac{1}{T}\sum_{t=1}^{T} (p_t - \bar{p})^2}$
    \State \Return $(\bar{p}, \sigma)$
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[ht]
\caption{Score-Level CTGAN Augmentation for Decision Agent Training}
\label{alg:eswa_ctgan}
\begin{algorithmic}[1]
    \State \textbf{Input:} Trained agents $A_{\text{sem}}, A_{\text{beh}}$; training data $\{\mathbf{z}_i\}, \{\mathbf{b}_i\}$; labels $\{y_i\}$
    \State \textbf{Output:} Augmented score dataset $\tilde{\mathcal{D}}_S$ for training $A_{\text{dec}}$
    \Statex \textbf{// Step 1: Collect score tuples}
    \For{each training sample $i$}
        \State $(\bar{p}_{\text{sem}}^{(i)}, \sigma_{\text{sem}}^{(i)}) \gets$ Alg.~\ref{alg:eswa_mc_dropout}$(A_{\text{sem}}, \mathbf{z}_i, T)$
        \State $(\bar{p}_{\text{beh}}^{(i)}, \sigma_{\text{beh}}^{(i)}) \gets$ Alg.~\ref{alg:eswa_mc_dropout}$(A_{\text{beh}}, \mathbf{b}_i, T)$
        \State $s_i \gets [\bar{p}_{\text{sem}}^{(i)}, \bar{p}_{\text{beh}}^{(i)}]$
    \EndFor
    \State Construct $\mathcal{D}_S = \{(s_i, y_i)\}$
    \Statex \textbf{// Step 2: Train CTGAN in score space}
    \State Train CTGAN generator $G$ and discriminator $D$ on $\mathcal{D}_S$ conditioned on labels $y_i$
    \State Generate synthetic samples $\tilde{s}_j = G(z_j, y_j)$ and form $\tilde{\mathcal{D}}_S = \{(\tilde{s}_j, y_j)\}$
    \State \Return $\tilde{\mathcal{D}}_S$
\end{algorithmic}
\end{algorithm}


\section{Uncertainty-Aware Triage Policy}
\label{sec:eswa_policy}

\subsection{Policy Design and Thresholds}

The triage orchestrator converts the pair $(\hat{p}, \sigma_\text{max})$ into one of three operational actions — \textsc{Auto-Contain}, \textsc{Escalate}, or \textsc{Allow} — using two pairs of thresholds. The general pair $(\tau, \kappa)$ defines the escalation boundary, and the stricter pair $(\tau_\text{high}, \kappa_\text{low})$ defines the autonomous containment region. These satisfy the ordering constraints:
\begin{equation}
\tau \leq \tau_\text{high}, \qquad \kappa_\text{low} \leq \kappa,
\label{eq:eswa_ordering}
\end{equation}
meaning that autonomous containment requires higher fused risk \emph{and} lower uncertainty than escalation. Axis-aligned thresholds are deliberately chosen over learned non-linear boundaries to preserve interpretability and auditability in regulated operational environments.

\subsection{Decision Rules}

The orchestrator applies:
\begin{align}
\text{AUTO-CONTAIN} &\quad \text{if} \quad \hat{p} \geq \tau_\text{high} \;\wedge\; \sigma_\text{max} \leq \kappa_\text{low}, \label{eq:eswa_auto} \\
\text{ESCALATE}     &\quad \text{if} \quad \hat{p} \geq \tau \;\vee\; \sigma_\text{max} > \kappa, \label{eq:eswa_esc} \\
\text{ALLOW}        &\quad \text{otherwise.} \label{eq:eswa_allow}
\end{align}
This logic ensures: (a) automatic containment is restricted to high-confidence, low-uncertainty predictions; (b) human escalation is triggered by either elevated risk or elevated epistemic uncertainty; (c) samples with low risk and low uncertainty are autonomously allowed without analyst involvement. The complete policy decision procedure is formalised in Algorithm~\ref{alg:eswa_triage}.

\subsection{Policy Optimisation}

Thresholds $(\tau, \kappa, \tau_\text{high}, \kappa_\text{low})$ are jointly selected by Bayesian optimisation using the Tree-structured Parzen Estimator (TPE) \cite{optuna2019}, maximising the scalarised objective:
\begin{equation}
J(\tau, \kappa) = \text{BalAcc}(\tau, \kappa) - \lambda \cdot \text{EscRate}(\tau, \kappa),
\label{eq:eswa_objective}
\end{equation}
subject to Equation~\eqref{eq:eswa_ordering}. The trade-off parameter $\lambda = 0.5$ balances detection accuracy against escalation workload. Two operational configurations are derived: a \emph{safety-optimal} configuration maximising balanced accuracy, and a \emph{low-escalation} configuration minimising escalation volume at near-equal accuracy.

\begin{algorithm}[ht]
\caption{Uncertainty-Aware Triage Policy}
\label{alg:eswa_triage}
\begin{algorithmic}[1]
    \State \textbf{Input:} Fused risk $\hat{p}$, agent uncertainties $\sigma_{\text{sem}}, \sigma_{\text{beh}}$
    \State \textbf{Input:} Thresholds $\tau$, $\tau_{\text{high}}$, $\kappa$, $\kappa_{\text{low}}$
    \State \textbf{Output:} Decision $\in \{\text{AUTO-CONTAIN}, \text{ESCALATE}, \text{ALLOW}\}$
    \State $\sigma_{\max} \gets \max(\sigma_{\text{sem}}, \sigma_{\text{beh}})$
    \If{$\hat{p} \geq \tau_{\text{high}}$ \textbf{and} $\sigma_{\max} \leq \kappa_{\text{low}}$}
        \State \Return \textbf{AUTO-CONTAIN} \Comment{high risk, low uncertainty}
    \ElsIf{$\hat{p} \geq \tau$ \textbf{or} $\sigma_{\max} > \kappa$}
        \State \Return \textbf{ESCALATE} \Comment{risky or uncertain}
    \Else
        \State \Return \textbf{ALLOW} \Comment{benign and confident}
    \EndIf
\end{algorithmic}
\end{algorithm}


\section{Policy Analysis}
\label{sec:eswa_policyanalysis}

The triage mechanism governs the joint behaviour of the fused probability $\hat{p}$ and the maximal epistemic uncertainty $\sigma_\text{max}$. The policy partitions the space
\begin{equation}
\mathcal{X} = \bigl\{(\hat{p}, \sigma_\text{max}) \in [0,1] \times [0,1]\bigr\}
\label{eq:eswa_policyspace}
\end{equation}
into three disjoint regions corresponding to \textsc{Allow}, \textsc{Escalate}, and \textsc{Auto-Contain}. The decision boundaries are defined implicitly by the inequalities in Equations~\eqref{eq:eswa_auto}--\eqref{eq:eswa_allow}: the vertical lines $\hat{p} = \tau$ and $\hat{p} = \tau_\text{high}$ together with the horizontal lines $\sigma_\text{max} = \kappa$ and $\sigma_\text{max} = \kappa_\text{low}$ generate a partitioned rectangle whose subregions determine the triage outcome.

Samples located near the boundary corners $(\tau_\text{high}, \kappa_\text{low})$ and $(\tau, \kappa)$ exhibit the greatest instability under adversarial perturbation. However, due to the monotonic structure of the fusion classifier, the gradient of $\hat{p}$ is largest where semantic evidence dominates, meaning the neighbourhood of $(\tau_\text{high}, \kappa_\text{low})$ tends to be sparsely populated — an important stability property.

The threshold optimisation objective in Equation~\eqref{eq:eswa_objective} identifies threshold pairs that shift these decision boundaries. Increasing $\tau$ reduces the escalation region but simultaneously risks enlarging the allow region unless offset by a simultaneous adjustment to $\kappa$. The calibrated trade-off therefore emerges from solving the non-convex problem of maximising $J(\tau,\kappa)$ while maintaining robustness to the uncertainty geometry in Equation~\eqref{eq:eswa_policyspace}. This interplay between fused risk, epistemic uncertainty, and threshold selection constitutes the mathematical core of the Agentic SABRE policy framework.


\section{Threat Model}
\label{sec:eswa_threatmodel}

The operational setting assumes an adversary capable of deploying ransomware samples that vary in semantic structure, behavioural dynamics, or both. The defender observes two forms of telemetry: a semantic representation $\mathbf{z}_i \in \mathbb{R}^{d_s}$ encoded from static artefacts and a behavioural representation $\mathbf{b}_i \in \mathbb{R}^{d_b}$ extracted from temporal I/O activity. The adversary operates under the constraint that behavioural logs and static metadata cannot be forged arbitrarily without compromising the malware's execution.

The threat model considers adversarial manoeuvres that attempt to reduce the classifier's confidence while preserving functional attack behaviour. These manoeuvres can target the semantic agent by modifying static descriptors; however, such modifications typically shift the semantic embedding distribution, increasing the Wasserstein distance in Equation~\eqref{eq:eswa_wass_sem} only marginally, and often increasing epistemic uncertainty. Similarly, behavioural mimicry attacks attempt to disguise malicious activity so that the derived empirical distributions
\begin{equation}
p(\mathbf{b} \mid y=1), \qquad p(\mathbf{b} \mid y=0),
\label{eq:eswa_beh_dists}
\end{equation}
appear closer to each other. Such mimicry produces elevated uncertainty in the behavioural agent due to the mismatch between expected and observed feature variance.

The model assumes that the attacker does not possess knowledge of the triage parameters $\tau$, $\kappa$, $\tau_\text{high}$, $\kappa_\text{low}$, nor the calibration temperature applied to the fusion classifier. Even if such knowledge were available, the attacker would still face the constraint that reducing the fused probability $\hat{p}$ (Equation~\eqref{eq:eswa_fusedp}) necessarily increases behavioural deviation, thus raising the uncertainty term $\sigma_\text{max}$ (Equation~\eqref{eq:eswa_sigmamax}). Consequently, ambiguous or adversarial samples are redirected to human analysts rather than executed automatically, providing robustness against a broad class of evasion strategies.

Global feature importance for each agent is assessed via permutation importance: the drop in AUC when feature $j$ is randomly permuted across the test set:
\begin{equation}
I_j = \text{AUC}_\text{orig} - \text{AUC}_j.
\label{eq:eswa_permimp}
\end{equation}
For the Behavioural Agent, the highest $I_j$ values correspond to dispersion-based statistics: \texttt{read\_LBA\_variance}, \texttt{write\_LBA\_variance}, \texttt{mem\_read\_GPA\_variance}, and \texttt{mem\_write\_GPA\_variance}, confirming that ransomware distinguishes itself through irregular, spatially bursty memory and storage access footprints rather than raw activity volume.

\subsection{Counterfactual Analysis}

Counterfactual explanations identify the minimal perturbation $\tilde{\mathbf{b}}$ to a behavioural feature vector $\mathbf{b}$ required to flip the agent's decision below a threshold $\theta = 0.49$:
\begin{equation}
\Delta^\star = \arg\min_{\tilde{\mathbf{b}} \in \mathcal{N}_\epsilon(\mathbf{b})} \|\tilde{\mathbf{b}} - \mathbf{b}\|_2,
\quad \text{subject to} \quad p_\text{beh}(\tilde{\mathbf{b}}) \leq \theta.
\label{eq:eswa_cf}
\end{equation}
Counterfactual experiments on 50 high-confidence malicious samples show that only small relative reductions in LBA and GPA variance are sufficient to cross the decision boundary, with mean perturbation norm $\mathbb{E}[\|\Delta^\star\|_2] \approx 0.12$. \section{Datasets and Experimental Setup}
\label{sec:eswa_setup}

\subsection{Datasets}

\textbf{RDset.} RDset \cite{mathur2020ransomware} contains 138,047 PE-file records (41,123 ransomware; 96,924 benign) with 384-dimensional semantic embedding vectors. The dataset spans multiple ransomware families and is used to train and evaluate the Semantic Agent. Evaluation uses stratified 80/20 train-test splits with 2,000 test samples per class.

\textbf{RanSMAP.} The RanSAP / RanSMAP dataset \cite{hirano2022ransap, hirano2025ransmap} contains 11,820 execution traces drawn from 24 ransomware families and benign workloads across diverse hardware configurations. The 16-dimensional feature vectors are extracted from 30-second sliding windows. The native class ratio is approximately 598:1. Balanced evaluation uses 1,000 samples per class; the full imbalanced distribution is also evaluated to characterise real-world deployment behaviour.

\textbf{Cross-source fusion rationale.} RDset and RanSMAP contain no overlapping samples — RDset consists of static PE metadata while RanSMAP records runtime execution traces from instrumented hypervisors. Raw features are never merged; fusion occurs exclusively at the score level, reflecting the realistic SOC scenario in which a static sandbox scanner and a runtime endpoint monitor report simultaneously on the same host. CTGAN labels use binary $y_i \in \{0, 1\}$ (benign/ransomware) without modification.

\textbf{Dataset limitations.} Neither dataset includes post-2021 ransomware families such as Cl0p, BlackCat/ALPHV, or LockBit 3.0. Generalisation to modern ransomware lineages is identified as a priority direction for future work. RDset does not employ a family-wise or temporal split: samples are partitioned at the binary level, so families present in the training set may appear under different instances in the test set, introducing the risk of structural similarity bias.

\subsection{Feature Extraction and Preprocessing}

Semantic embeddings are computed from concatenated PE attribute strings using a pre-trained sentence-transformer \cite{ReimersG19}. Behavioural features are computed via sliding-window statistics (variance, entropy, count) over 30-second activity windows. SMOTE \cite{chawla2002smote} is applied independently to each dataset to mitigate class imbalance at the feature level before agent training. Score-level CTGAN augmentation is applied after base-agent training, enriching rare high-risk score configurations without altering the learned agent representations.

\subsection{Evaluation Metrics}

Performance is evaluated using: accuracy, AUC (Area Under the ROC Curve), and confusion-matrix-derived metrics (TN, FP, FN, TP). Additionally, the \emph{escalation rate} — the fraction of samples routed to ESCALATE — is reported as a primary operational cost metric, since escalated samples require analyst attention and introduce response latency. Reductions in escalation volume at fixed recall correspond directly to deployability improvements.

\subsection{Computational Complexity and Runtime Performance}
\label{sec:eswa_complexity}

\subsubsection*{Training Complexity of CNN Agents}

Each CNN agent employs a 1D convolutional architecture of depth $L=3$, kernel size $K=3$, and $C=64$ filters per layer. For a training set of $N$ samples, the per-agent cost over $E$ epochs is $\mathcal{O}(E \cdot N \cdot L \cdot K \cdot C^2)$, linear in both $N$ and $E$.

\subsubsection*{Monte Carlo Dropout Score Generation}

The per-sample MC Dropout cost is $\mathcal{O}(T \cdot L \cdot K \cdot C^2)$. With $T = 30$, each agent requires approximately 2--5\,ms per stochastic pass on CPU, yielding an MC estimate in $\approx 60$--$150$\,ms per agent.

\subsubsection*{CTGAN Score-Space Augmentation}

Score-space augmentation trains a generator and discriminator over $N_s$ real score vectors $\mathbf{s} \in \mathbb{R}^{2}$. Because the score matrix is far smaller than the raw feature matrices, CTGAN fitting is tractable; empirically, $E_\text{CTGAN} = 200$ epochs complete in approximately 5--10\,min on CPU.

\subsubsection*{Total Pipeline Training Complexity}

Combining all components, the complete training complexity is:
\begin{align}
\mathcal{T} = \mathcal{O}\Bigl(
  &\;2(E{+}T)\,N\,L\,K\,C^2 \nonumber\\
  &+\; E_\text{CTGAN}\,N_s \bigl[\textstyle\sum_i g_i g_{i+1} + \sum_j d_j d_{j+1}\bigr] \nonumber\\
  &+\; E_\text{MLP}\,N_\text{aug}\,h^2 \nonumber\\
  &+\; T_\text{TPE} \bigl(n_\text{obs}\log n_\text{obs} + N_\text{val}\bigr)
\Bigr),
\label{eq:eswa_total_complexity}
\end{align}
where the four terms correspond respectively to CNN agent training and MC score generation, CTGAN score-space augmentation, Decision MLP fitting, and TPE threshold optimisation. The first term scales linearly in $N$; the CTGAN term is the practical bottleneck but remains tractable because the score matrix is orders of magnitude smaller than the raw feature matrices.

\subsubsection*{Measured Runtime Performance}

Table~\ref{tab:eswa_runtime} reports empirically measured inference latency and throughput per SABRE component on GPU. The Behavioural CNN requires 1.94\,ms (p50) for $T=10$ MC Dropout passes — a $3.7\times$ overhead relative to a single deterministic forward pass (0.52\,ms). At a 10-second telemetry window, this supports over 2,000 concurrent monitored streams. The agents are compact: the Behavioural CNN has only 8,385 parameters (32.8\,KB), making it suitable for endpoint deployment.

\section{Ablation Studies}
\label{sec:eswa_ablation}

This section isolates the contribution of individual architectural components — CTGAN augmentation, uncertainty inputs, and modality contributions — by systematically removing each element and measuring the resulting performance degradation.

\subsection{Effect of CTGAN Score-Space Augmentation}

The influence of CTGAN augmentation is quantified by removing it from the fusion stage. CTGAN learns a generator such that the synthetic distribution
\begin{equation}
\tilde{\mathcal{D}}_\mathbf{s} \approx p(\mathbf{s} \mid y),
\label{eq:eswa_ctgan_dist}
\end{equation}
producing synthetic samples that expand the score manifold. As shown in Table~\ref{tab:eswa_ablation_fusion}, removing CTGAN reduces the RanSMAP AUC from 0.540 to 0.514, indicating that density enrichment of $\mathbf{s}$ contributes to more robust decision boundaries. Replacing the trained fusion MLP with a naive score mean ($\hat{p}_\text{mean} = \frac{1}{2}(p_\text{sem} + p_\text{beh})$) performs significantly worse on RanSMAP due to the weak correlation of $p_\text{beh}$ with ground truth.

\subsection{Modal Contribution Ablation}

To isolate the contribution of each agent, we consider two restricted settings: (i) semantic ablation $p_\text{fus}^{(-\text{sem})}$ (behavioural only), and (ii) behavioural ablation $p_\text{fus}^{(-\text{beh})}$ (semantic only). In the absence of semantic information, behavioural counterfactual norms decrease, indicating that certain evasive trajectories become feasible through execution-only manipulations. Conversely, removing behavioural input enables purely structural evasion strategies. Neither ablated configuration preserves the super-additive adversarial cost in Equation~\eqref{eq:eswa_adv_cost}, confirming that robustness and interpretability are jointly maximised only when both modalities are present.


\section{Discussion}
\label{sec:eswa_discussion}

\subsection{Distributional Asymmetry and Wasserstein Distance}

The experiments highlight a marked asymmetry between the discriminative structures of the semantic and behavioural feature spaces. The class-conditioned distributions in semantic space can be characterised by the Wasserstein-2 distance:
\begin{equation}
d_\text{sem} = W_2\bigl(p(\mathbf{z} \mid y=1),\, p(\mathbf{z} \mid y=0)\bigr),
\label{eq:eswa_wass_sem}
\end{equation}
and likewise for behavioural data:
\begin{equation}
d_\text{beh} = W_2\bigl(p(\mathbf{b} \mid y=1),\, p(\mathbf{b} \mid y=0)\bigr).
\label{eq:eswa_wass_beh}
\end{equation}
The empirical results strongly suggest that $d_\text{sem} \gg d_\text{beh}$, explaining why semantic predictions cluster near $\{0,1\}$ while behavioural predictions exhibit broad dispersion. The fusion model exploits this asymmetry by treating the semantic component as a strong positive signal whenever uncertainty is low and treating the behavioural component primarily as a modulator of $\sigma_\text{max}$.

\subsection{Operational Implications}

Agentic SABRE demonstrates that uncertainty-aware triage is not merely a theoretical construct but a practically deployable mechanism. The 4.9\% reduction in false escalations at equal recall on RanSMAP translates directly to reduced analyst workload in a live SOC, where each escalated sample requires human review time. The formal threshold ordering constraints (Equation~\eqref{eq:eswa_ordering}) ensure that the AUTO-CONTAIN region is always a strict subset of the ESCALATE region, providing a provable safety guarantee: no sample can be autonomously contained unless it would also qualify for escalation under the looser thresholds.

The modular design enables two forms of operational update that are impractical in monolithic systems. First, the triage thresholds can be recalibrated via the TPE objective (Equation~\eqref{eq:eswa_objective}) on a new validation set without retraining any model — a minutes-long operation. Second, each agent can be retrained independently on new data without affecting the other agent or the Decision Agent.


\section{Limitations}
\label{sec:eswa_limitations}

Three principal limitations constrain the current design. First, the fusion mechanism (Equation~\eqref{eq:eswa_fusedp}) assumes conditional independence between semantic and behavioural agent outputs; in operational settings, PE structure and I/O patterns may exhibit dependencies that violate this assumption. A normalising flow or attention-based fusion function could model the joint likelihood more accurately. Second, MC Dropout may under-estimate epistemic uncertainty under strong non-stationarity — a risk in rapidly evolving ransomware ecosystems. Deep ensembles or conformal prediction frameworks \cite{yumlembam2024comprehensive} could provide better-calibrated uncertainty at higher computational cost. Third, the counterfactual analysis reveals that the Behavioural Agent's decision boundary is fragile under variance-reduction attacks, pointing to a need for adversarially robust training.

The triage thresholds are optimised offline and are not updated during deployment. In dynamic environments where the score distribution shifts over time — due to concept drift, new family emergence, or changing benign workload patterns — static thresholds can become miscalibrated. A natural extension would be an adaptive thresholding mechanism, such as a sliding-window recalibration that re-optimises Equation~\eqref{eq:eswa_objective} on a rolling buffer of analyst-labelled decisions.

Finally, the family holdout evaluation (AUROC 0.707, Table~\ref{tab:eswa_multiseed}) confirms that the Behavioural Agent generalises only partially to unseen ransomware families. The uncertainty mechanism mitigates this by routing family-holdout samples to \textsc{ESCALATE} rather than \textsc{AUTO-CONTAIN}, but improving zero-shot generalisation remains an important future direction.


\section{Chapter Summary}
\label{sec:eswa_summary}

This chapter presented Agentic SABRE, a multi-agent uncertainty-aware framework for adaptive ransomware detection. Moving beyond the single-agent approach of the preceding chapter, Agentic SABRE decomposes detection into a Semantic Agent operating on PE-header embeddings and a Behavioural Agent operating on runtime telemetry, each equipped with Monte Carlo Dropout uncertainty estimation. A score-space CTGAN augmentation strategy and a two-hidden-layer Decision Agent MLP fuse the agents' outputs into a calibrated risk estimate. A formal uncertainty-aware triage policy with Bayesian-optimised thresholds routes high-confidence, low-uncertainty predictions to autonomous containment, uncertain predictions to human analysts, and low-risk predictions to automatic allowance.

Empirical results on RDset and RanSMAP demonstrate near-perfect fusion performance on the semantic dataset while correctly managing the high-uncertainty behavioural regime through conservative escalation. Generalisation evaluation across four evaluation splits confirms temporal and hardware robustness while identifying family holdout as the principal generalisation challenge. Ablation studies quantify the contribution of each architectural component: removing CTGAN reduces RanSMAP AUC from 0.540 to 0.514; removing uncertainty inputs increases false negatives from 43,656 to 58,441. Permutation importance, gradient saliency, and counterfactual analysis confirm that both agents rely on interpretable, ransomware-relevant signals, and that the fusion architecture enforces a super-additive adversarial cost that requires coordinated manipulation of both modalities to evade.

The following chapter extends this two-agent framework to a three-agent system by introducing a Knowledge Agent trained on practitioner threat-intelligence discourse, a Peer Consultation Protocol that enables uncertain agents to query their peers before fusion, and an Expert Feedback Loop that incorporates analyst corrections to incrementally adapt the Decision Agent against concept drift.
